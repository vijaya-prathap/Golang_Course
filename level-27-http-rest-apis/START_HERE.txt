================================================================================
                      THE BIG PICTURE
================================================================================

What is an HTTP Handler?
  → Anything with a ServeHTTP(w http.ResponseWriter, r *http.Request) method
  → That's it - no base class, no framework object, one method
  → http.HandlerFunc adapts an ordinary function into a Handler

Why This Level Matters:
  → Every Go web framework (Gin included, Level 28) is built ON TOP of
    net/http's Handler interface - learn this and every framework
    afterward is just convenience layered on what you already understand
  → REST APIs are how most real Go services talk to the outside world

================================================================================
                 THE core INTERFACE
================================================================================

  type Handler interface {
      ServeHTTP(ResponseWriter, *Request)
  }

  type HandlerFunc func(ResponseWriter, *Request) // adapts a func

  func hello(w http.ResponseWriter, r *http.Request) {
      fmt.Fprintln(w, "Hello, World!")
  }
  // http.HandlerFunc(hello) now satisfies http.Handler

================================================================================
                 MODERN ROUTING (Go 1.22+)
================================================================================

  mux := http.NewServeMux()
  mux.HandleFunc("GET /items", listItems)
  mux.HandleFunc("POST /items", createItem)
  mux.HandleFunc("GET /items/{id}", getItem)
  mux.HandleFunc("DELETE /items/{id}", deleteItem)

  id := r.PathValue("id") // read a matched wildcard

VERIFIED, REAL BEHAVIOR: registering GET/POST /items but sending a PUT to
/items returns 405 Method Not Allowed automatically - ServeMux does this
without any code from you.

================================================================================
                    READING AND WRITING
================================================================================

Reading:
  id := r.PathValue("id")
  q := r.URL.Query().Get("q")
  json.NewDecoder(r.Body).Decode(&req)   // always check the error!

Writing (ORDER MATTERS):
  w.Header().Set("Content-Type", "application/json")  // 1. headers
  w.WriteHeader(http.StatusCreated)                     // 2. status
  json.NewEncoder(w).Encode(resp)                        // 3. body

================================================================================
                    THE MIDDLEWARE PATTERN
================================================================================

Middleware is a function that takes a Handler and returns a new one:

  func Logging(logger *log.Logger, next http.Handler) http.Handler {
      return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
          start := time.Now()
          next.ServeHTTP(w, r)
          logger.Printf("%s %s (%s)", r.Method, r.URL.Path, time.Since(start))
      })
  }

Because input and output are both http.Handler, layers compose:
  handler := Logging(logger, RequestID(mux))

================================================================================
                 TESTING: TWO TOOLS, TWO JOBS
================================================================================

httptest.NewRecorder - fast, in-process, unit-test ONE handler:
  req := httptest.NewRequest(http.MethodGet, "/hello", nil)
  rec := httptest.NewRecorder()
  HelloHandler(rec, req)
  // rec.Code, rec.Body.String()

httptest.NewServer - real (loopback-only) TCP round trip, tests the WHOLE
stack:
  server := httptest.NewServer(mux)
  defer server.Close()
  resp, _ := server.Client().Get(server.URL + "/hello")

Both are fully offline - NewRecorder touches no network at all, and
NewServer binds only to 127.0.0.1 with an OS-assigned port.

================================================================================
                    CONTEXT AND CONSISTENT ERRORS
================================================================================

Context (bridging Level 24):
  ctx, cancel := context.WithTimeout(r.Context(), 2*time.Second)
  defer cancel()
  // select on the work finishing vs <-ctx.Done()

Errors (bridging Level 16) - ONE consistent JSON shape everywhere:
  type errorResponse struct { Error string `json:"error"` }

  func writeError(w http.ResponseWriter, err error) {
      status := http.StatusInternalServerError
      switch {
      case errors.Is(err, ErrNotFound):
          status = http.StatusNotFound
      }
      w.Header().Set("Content-Type", "application/json")
      w.WriteHeader(status)
      json.NewEncoder(w).Encode(errorResponse{Error: err.Error()})
  }

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Calling Write before WriteHeader
  w.Write([]byte("created"))
  w.WriteHeader(http.StatusCreated)   // too late - already sent 200!

✅ RIGHT
  w.WriteHeader(http.StatusCreated)
  w.Write([]byte("created"))

---

❌ WRONG: Ignoring the JSON decode error
  json.NewDecoder(r.Body).Decode(&req)   // malformed body goes unnoticed

✅ RIGHT
  if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
      http.Error(w, "invalid JSON body", http.StatusBadRequest)
      return
  }

---

❌ WRONG: A goroutine that ignores context cancellation
  go func() {
      time.Sleep(10 * time.Second)   // keeps running even if ctx is done
      result <- "done"
  }()

✅ RIGHT: select on ctx.Done() inside the goroutine too

---

❌ WRONG: Not closing an outgoing response body
  resp, _ := http.Get(someURL)
  data, _ := io.ReadAll(resp.Body)   // leaks the connection

✅ RIGHT: defer resp.Body.Close() right after checking the error

                      QUICK FAQ
================================================================================

Q: Do I need a routing framework to build a real REST API in Go?
A: Not necessarily - since Go 1.22, http.ServeMux handles method-specific
   routes and path wildcards natively. Level 28 (Gin) adds convenience on
   top of exactly this model.

Q: What's the difference between httptest.NewRecorder and NewServer?
A: NewRecorder is an in-process fake ResponseWriter - fast, no network.
   NewServer starts a real (loopback-only) TCP server - use it to prove
   routing and middleware work together end to end.

Q: Why derive context.WithTimeout from r.Context() and not Background()?
A: r.Context() is already canceled if the client disconnects. Deriving
   from it means your handler respects BOTH your timeout and the client
   giving up.

Q: Is any of this exercise verification doing real network access?
A: No - httptest.NewRecorder touches no network, and httptest.NewServer
   binds only to 127.0.0.1 with an OS-assigned port. Everything in this
   level runs fully offline.
