================================================================================
                      THE BIG PICTURE
================================================================================

What's a Package?
  → A directory containing Go files
  → All files in one directory belong to the same package
  → Example: "math/" directory is a package

Why Packages?
  → Organize code by responsibility
  → Reuse code across projects
  → Control what's public/private
  → Manage complexity

Key Insight:
  → One directory = One package
  → One package = Can have multiple files
  → Files in same package can access each other's code
  → Other packages can only access exported (capitalized) code

================================================================================
                    THE CAPITALIZATION RULE
================================================================================

This is CRITICAL in Go:

UPPERCASE first letter = Exported (public)
lowercase first letter = Unexported (private)

Examples:

✅ EXPORTED (public - other packages can see)
   func GetName() string { }
   var GlobalCount int
   type User struct { }
   const MaxSize = 100

❌ UNEXPORTED (private - only this package can see)
   func getName() string { }
   var privateCount int
   type user struct { }
   const minSize = 100

================================================================================
                    A SIMPLE EXAMPLE
================================================================================

Let's create a simple project:

Project Structure:
  myapp/
  ├── go.mod
  ├── main.go
  └── helpers/
      └── strings.go

Step 1: Setup
  mkdir myapp && cd myapp
  go mod init myapp

Step 2: Create helpers package
  mkdir helpers
  
Step 3: Create helpers/strings.go
  package helpers
  
  func Reverse(s string) string {
      runes := []rune(s)
      for i, j := 0, len(runes)-1; i < j; i, j = i+1, j-1 {
          runes[i], runes[j] = runes[j], runes[i]
      }
      return string(runes)
  }

Step 4: Create main.go
  package main
  
  import (
      "fmt"
      "myapp/helpers"
  )
  
  func main() {
      result := helpers.Reverse("hello")
      fmt.Println(result)  // Output: olleh
  }

Step 5: Run
  go run .

That's it! You just created a package and used it from main!

================================================================================
                      KEY CONCEPTS SUMMARY
================================================================================

1. PACKAGES
   - One directory = One package
   - All Go files in a directory must have same package name
   - Package name usually matches directory name

2. EXPORTS
   - Uppercase = Exported (public)
   - lowercase = Unexported (private)
   - Applies to functions, variables, types, constants

3. IMPORTS
   - Import path must match module name (from go.mod)
   - Import path uses forward slashes: "myapp/helpers"
   - Import relative to module root, not current directory

4. INIT FUNCTIONS
   - func init() { } runs automatically when package loads
   - Runs before main()
   - Useful for package setup/initialization

5. FILE ORGANIZATION
   - Multiple files in same package can access each other
   - Each file starts with: package packagename
   - Files don't need to match directory exactly

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Wrong package name
   Directory: myapp/helpers/
   File: package utilities  (doesn't match!)

✅ RIGHT: Package name matches directory
   Directory: myapp/helpers/
   File: package helpers  (matches!)

---

❌ WRONG: Trying to access unexported outside package
   // In helpers/strings.go
   func reverse(s string) string { }  (lowercase)
   
   // In main.go
   helpers.reverse("hello")  (ERROR!)

✅ RIGHT: Use capitalized function
   // In helpers/strings.go
   func Reverse(s string) string { }  (UPPERCASE)
   
   // In main.go
   helpers.Reverse("hello")  (OK!)

---

❌ WRONG: Relative import paths
   import "./helpers"
   import "../utils"

✅ RIGHT: Absolute import paths
   import "myapp/helpers"
   import "myapp/utils"

================================================================================
                      FILE ORGANIZATION
================================================================================

The Directory Structure:

myapp/
├── go.mod                    ← Your module definition
├── go.sum                    ← Dependencies (auto-generated)
├── main.go                   ← Entry point (package main)
├── models/                   ← Package for data structures
│   ├── user.go
│   └── product.go
├── services/                 ← Package for business logic
│   └── user_service.go
└── handlers/                 ← Package for output handlers
    └── handlers.go

Key Points:
- Each directory is ONE package
- main.go is in package main (only directory with main())
- Other directories create their own packages
- All files in a directory share the same package name
