================================================================================
                      THE BIG PICTURE
================================================================================

What is database/sql?
  → A standard interface over relational databases: sql.DB, sql.Rows,
    sql.Tx, and friends - paired with a driver that does the real talking
  → The driver is a separate module, imported purely for its side effect
    (blank import: _ "modernc.org/sqlite") to register itself

Why database/sql Matters:
  → Every API and program you've built so far has kept data in memory,
    gone the instant the process exits
  → This is how real applications persist data between runs, across
    restarts, and across many concurrent users

================================================================================
                 CONNECTING: LAZY OPEN, EAGER PING
================================================================================

  db, err := sql.Open("sqlite", "file::memory:?cache=shared")
  defer db.Close()
  db.SetMaxOpenConns(1)   // in-memory SQLite needs exactly ONE connection

  db.Ping()   // sql.Open does NOT verify connectivity - Ping() does, right now

  sql.DB is a POOL, not a single connection. Query/Exec/QueryRow each borrow
  a connection, use it, and return it - you almost never touch one directly.

  THE SQLITE GOTCHA: plain ":memory:" gives every new pooled connection its
  OWN separate, empty database. file::memory:?cache=shared + SetMaxOpenConns(1)
  routes every call through the SAME connection, avoiding this entirely.

================================================================================
                 READING DATA: QUERY VS QUERYROW
================================================================================

  Many rows expected:
    rows, err := db.Query(`SELECT id, title FROM books`)
    defer rows.Close()                    // ALWAYS
    for rows.Next() {
        rows.Scan(&id, &title)
    }
    if err := rows.Err(); err != nil { }  // check AFTER the loop too

  Zero-or-one row expected:
    var title string
    err := db.QueryRow(`SELECT title FROM books WHERE id = ?`, id).Scan(&title)
    if errors.Is(err, sql.ErrNoRows) {
        // NOT FOUND is a normal case, not a crash
    }

================================================================================
                 WRITING DATA: ALWAYS PARAMETERIZED
================================================================================

  result, err := db.Exec(`INSERT INTO books (title) VALUES (?)`, title)
  id, _ := result.LastInsertId()
  affected, _ := result.RowsAffected()

  THE ONE RULE, NO EXCEPTIONS:
    ✅ db.Query(`WHERE author = ?`, userInput)          -- SAFE
    ❌ fmt.Sprintf(`WHERE author = '%s'`, userInput)     -- NEVER

  Verified in Exercise 4: passing a string that LOOKS like a SQL injection
  attempt through the parameterized path returns zero rows - it's compared
  literally, as data, and never gets to alter the query's structure.

================================================================================
                 TRANSACTIONS: DEFER-ROLLBACK-IF-NOT-COMMITTED
================================================================================

  tx, err := db.Begin()
  committed := false
  defer func() {
      if !committed {
          tx.Rollback()      // safety net - runs on ANY early return
      }
  }()

  tx.Exec(...)   // step 1
  tx.Exec(...)   // step 2

  tx.Commit()
  committed = true

  Verified for real (Exercise 7): a CHECK constraint rejects a mid-transaction
  UPDATE, the deferred Rollback() runs, and stock/order counts end up EXACTLY
  where they started - not partially applied.

================================================================================
                      KEY CONCEPTS SUMMARY
================================================================================

1. THE INTERFACE
   database/sql + a blank-imported driver (_ "modernc.org/sqlite")

2. THE POOL
   sql.Open is lazy; sql.DB is a pool; db.Ping() verifies eagerly

3. READING
   Query for many rows (Close+Err!), QueryRow for one (watch ErrNoRows)

4. WRITING
   Exec + sql.Result, ALWAYS parameterized with ? placeholders

5. STRUCTURE
   Prepared statements for repeated SQL; transactions for atomicity

6. CANCELLATION
   The *Context family (QueryContext, ExecContext, ...) - Level 24 bridge

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Forgetting rows.Close()
  rows, _ := db.Query(`SELECT * FROM books`)
  for rows.Next() { }   // connection leaked back to the pool late, or never

✅ RIGHT
  rows, err := db.Query(`SELECT * FROM books`)
  defer rows.Close()

---

❌ WRONG: String-concatenating SQL
  query := "SELECT * FROM books WHERE title = '" + userInput + "'"

✅ RIGHT
  db.Query(`SELECT * FROM books WHERE title = ?`, userInput)

---

❌ WRONG: Forgetting sql.ErrNoRows
  err := db.QueryRow(`...`, id).Scan(&b)
  if err != nil {
      log.Fatal(err)   // crashes just because id didn't exist!
  }

✅ RIGHT
  if errors.Is(err, sql.ErrNoRows) {
      // handle "not found" as a normal case
  }

---

❌ WRONG: Forgetting to Commit or Rollback
  tx, _ := db.Begin()
  tx.Exec(`UPDATE ...`)
  // ... nothing else - connection held forever

✅ RIGHT: the defer-rollback-if-not-committed pattern, every transaction

================================================================================
                      QUICK FAQ
================================================================================

Q: Why do I need a separate driver module for a "standard library" package?
A: database/sql only defines the interface. The driver (modernc.org/sqlite,
   blank-imported) is what actually speaks the database's protocol.

Q: Does sql.Open fail immediately if the database is unreachable?
A: No - it's lazy. Call db.Ping() right after if you need to know now.

Q: Why file::memory:?cache=shared instead of plain :memory:?
A: sql.DB is a connection pool. Plain :memory: gives every new pooled
   connection its own separate, empty database. The shared-cache DSN plus
   SetMaxOpenConns(1) fixes that by routing everything through one connection.

Q: What's the one rule that prevents SQL injection?
A: Every value goes through a ? placeholder, passed as a separate argument -
   never string-concatenated or Sprintf'd into the SQL text.

Q: How do I know a rollback actually undid everything?
A: Exercise 7 verifies it for real - a failed mid-transaction UPDATE gets
   rolled back, and the affected row ends up exactly where it started.
