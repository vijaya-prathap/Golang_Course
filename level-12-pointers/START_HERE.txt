Welcome to Level 12! You have completed the FUNDAMENTALS tier (Levels 0-11).
This level begins the OOP CONCEPTS tier, where pointers, structs, methods,
interfaces, and error handling connect into the patterns used in real Go code.

Pointers are often the point where Go starts to feel powerful: they let a
function modify a caller's value, let large structs be shared efficiently, and
let a program represent "not provided" with nil.

Do not bring C-pointer anxiety here. Go gives you useful references without
pointer arithmetic, manual allocation, manual freeing, or dangling pointers.

================================================================================
                            THE BIG PICTURE
================================================================================

A regular variable contains a value. A pointer contains the address where a
value lives:

  x = 42                         p = address of x

  x ┌──────────┐                 p ┌──────────────────┐
    │    42    │                   │ address of x     │ ──▶ x
    └──────────┘                   └──────────────────┘

The two essential operators are:

  p := &x      p gets the address of x
  value := *p  value gets the value stored at that address
  *p = 100     writes 100 into the value at that address

After *p = 100, x is also 100. There is one underlying value, reached by two
different expressions.

================================================================================
                        FIRST POINTER EXAMPLE
================================================================================

  package main

  import "fmt"

  func main() {
      x := 42
      p := &x

      fmt.Println(x)  // 42
      fmt.Println(*p) // 42

      *p = 100
      fmt.Println(x)  // 100
  }

Read the central lines as:

  p := &x     "p gets the address of x"
  *p = 100    "the value at p becomes 100"

The star symbol has two different jobs depending on position:

  var p *int  In a type: p is a pointer to int.
  *p          In an expression: follow p to its pointed-at value.

================================================================================
                                nil
================================================================================

The zero value of every pointer type is nil, which means "points at nothing."

  var p *int
  fmt.Println(p == nil) // true

Never dereference a pointer that might be nil:

  var p *int
  fmt.Println(*p) // runtime panic: nil pointer dereference

Instead, guard it first:

  if p != nil {
      fmt.Println(*p)
  } else {
      fmt.Println("no value")
  }

The normal fix for a nil panic is a clear nil check at the boundary of a
function. recover is only a last-resort safety net, not normal control flow.

================================================================================
                     POINTERS AND FUNCTION CALLS
================================================================================

Go always passes arguments by value. This includes pointers.

  func doubleValue(n int) {
      n *= 2 // changes only the copied number
  }

  func doublePointer(n *int) {
      *n *= 2 // writes through a copied address to the original number
  }

  x := 10
  doubleValue(x)
  // x is still 10

  doublePointer(&x)
  // x is now 20

A pointer does NOT make Go pass by reference. Go copies an address, and both
the original pointer and copied pointer name the same pointed-at value.

================================================================================
                         POINTERS TO STRUCTS
================================================================================

Pointers are most common with structs:

  type Player struct {
      name  string
      score int
  }

  func addPoints(p *Player, points int) {
      p.score += points
  }

  player := Player{name: "Alice", score: 100}
  addPoints(&player, 25)
  fmt.Println(player.score) // 125

Go automatically dereferences a struct pointer for field selection:

  p.score       idiomatic and preferred
  (*p).score    legal, but noisy

This will become pointer-receiver methods in Level 14.

================================================================================
                     ALLOCATION AND CONSTRUCTORS
================================================================================

Two forms create a value and give you a pointer:

  p := new(Point)          pointer to a zero-valued Point
  p := &Point{x: 3, y: 4}  pointer to an initialized Point

For structs, prefer the second form because it is concise and can initialize
the fields.

Returning an address of a local is safe:

  func newCounter() *Counter {
      c := Counter{}
      return &c
  }

Go's compiler sees that c must outlive the function, moves it to a safe
location when needed, and garbage collection keeps it alive while the returned
pointer remains reachable. There are no dangling pointers from this pattern.

================================================================================
                   WHEN POINTERS ARE NOT NEEDED
================================================================================

Do not add a pointer merely because a type can be mutated.

Slices and maps are already reference-like:

  func setFirst(nums []int) {
      nums[0] = 999
  }

  func addScore(scores map[string]int, name string, score int) {
      scores[name] = score
  }

Both changes are visible to the caller without *slice or *map parameters.

One important exception: append returns a potentially new slice header.

  func addItem(items []int) {
      items = append(items, 42) // caller does not receive the new header
  }

Use a return value:

  func addItem(items []int, value int) []int {
      return append(items, value)
  }

  items = addItem(items, 42)

================================================================================
                              SIMPLE RULES
================================================================================

Use a pointer parameter when:
  → A function must update an int, bool, string, or struct belonging to caller.
  → A large struct would be expensive to copy.
  → nil is meaningful, such as an optional configuration.

Usually do not use a pointer when:
  → A function only reads a small value.
  → Mutating elements of a slice or entries of a map.
  → You append to a slice; return the new slice instead.

================================================================================
                       COMMON MISTAKES TO AVOID
================================================================================

❌ Dereferencing nil

  var p *int
  fmt.Println(*p)

✅ Guard first

  if p != nil {
      fmt.Println(*p)
  }

---

❌ Expecting a value parameter to mutate a caller

  func levelUp(score int) { score += 100 }

✅ Use a pointer when mutation is part of the function contract

  func levelUp(score *int) { *score += 100 }

---

❌ Adding a pointer to a slice only to append

  func addItem(items *[]int) { ... }

✅ Return the new slice header

  func addItem(items []int, v int) []int {
      return append(items, v)
  }

---

❌ Taking the address of a range variable

  for _, v := range players {
      modify(&v) // v is a loop copy, not players[i]
  }

✅ Point at the real slice element

  for i := range players {
      modify(&players[i])
  }

                           KEY CONCEPTS SUMMARY
================================================================================

1. POINTER SHAPE
   var p *int
   p := &x
   value := *p

2. nil
   The zero value of a pointer; dereferencing it panics.

3. MUTATION ACROSS FUNCTIONS
   func f(x *int) can mutate caller's x through *x.

4. STRUCT POINTERS
   p.field is automatic dereference and is idiomatic.

5. ALLOCATION
   new(T) returns a zeroed *T; &T{} is preferred for structs.

6. SAFE CONSTRUCTORS
   Returning &localVar is safe because Go handles its lifetime.

7. SLICES AND MAPS
   Element and entry mutations need no pointer; return a slice after append.

================================================================================
                             QUICK FAQ
================================================================================

Q: Does Go pass pointers by reference?
A: No. Go always passes a copy. A pointer copy still reaches the same
   underlying value, which is why changes through it are visible.

Q: Can returning &localVariable cause a dangling pointer?
A: No. Go's compiler and garbage collector guarantee that the value stays
   alive for as long as the pointer can be used.

Q: Should every struct be passed as a pointer?
A: No. Use a pointer for mutation or to avoid copying a meaningfully large
   struct. Small read-only structs are often clearer by value.

Q: Why can a slice be changed without a pointer?
A: A copied slice header still points to the same backing array. Element writes
   are shared, although append changes only the local header unless returned.

Q: Does the address printed by %p matter?
A: No. It changes between runs. It is useful only for showing that pointers
   refer to the same value.

================================================================================
                       A COMPLETE POINTER EXAMPLE
================================================================================

This small program combines the most important Level 12 ideas: an initialized
struct pointer, a pointer parameter that mutates it, and a nil-safe helper.

  package main

  import "fmt"

  type Counter struct {
      name  string
      count int
  }

  func newCounter(name string) *Counter {
      return &Counter{name: name}
  }

  func increment(c *Counter) {
      if c == nil {
          return
      }
      c.count++
  }

  func valueOrZero(c *Counter) int {
      if c == nil {
          return 0
      }
      return c.count
  }

  func main() {
      clicks := newCounter("clicks")
      increment(clicks)
      increment(clicks)

      fmt.Println(clicks.name, valueOrZero(clicks))

      var missing *Counter
      fmt.Println("missing:", valueOrZero(missing))
  }

Output:

  clicks 2
  missing: 0

What to notice:

  1. newCounter returns an initialized *Counter using &Counter{...}.
  2. clicks is a pointer. It remains valid after newCounter returns.
  3. increment receives a copied pointer, but it reaches the same Counter.
  4. c.count uses Go's automatic struct-pointer dereference.
  5. Both pointer-taking functions explicitly handle nil at their boundary.

================================================================================
                      FINAL SELF-CHECK
================================================================================

Before moving on, make sure you can answer every question below without
running code:

[ ] What does &x produce?
    A pointer containing x's address.

[ ] What does *p do in an expression?
    It reads or writes the value at the address stored in p.

[ ] What is var p *int initialized to?
    nil.

[ ] What happens when you dereference nil?
    A runtime nil-pointer-dereference panic.

[ ] Does func f(p *int) use pass-by-reference?
    No. It receives a copy of the pointer (an address).

[ ] Which mutates the caller: func f(x int) or func f(x *int)?
    The pointer version, when it writes through *x.

[ ] How should you write a field through a struct pointer?
    p.field, not (*p).field.

[ ] Is return &localVar safe in Go?
    Yes. Go preserves the value's lifetime through escape analysis.

[ ] Do you need *map[string]int to add a map entry?
    No. A normal map parameter shares the same map data.

[ ] How do you make append visible to the caller?
    Return the result and assign it: items = addItem(items, value).

If any answer is uncertain, revisit the matching README section and complete
the corresponding exercise before proceeding to Level 13.
