================================================================================
                      THE BIG PICTURE
================================================================================

What is JSON?
  → A lightweight, text-based data format: objects {}, arrays [], strings,
    numbers, booleans, and null - that's the entire vocabulary
  → The default language of APIs, config files, and logs across every
    mainstream programming language

Why encoding/json Matters:
  → It's how your Go programs exchange structured data with the rest of
    the world - REST APIs (Level 27), config files, saved application state
  → It builds directly on things you already know: exported fields
    (Level 2), struct tags (Level 13), type assertions (Level 15), and
    error handling (Level 16)

================================================================================
                    MARSHAL AND UNMARSHAL
================================================================================

  data, err := json.Marshal(v)         // Go value -> JSON []byte
  err := json.Unmarshal(data, &v)      // JSON []byte -> Go value

  type Person struct {
      Name string
      Age  int
      City string
  }

  p := Person{Name: "Alice", Age: 30, City: "Lisbon"}
  data, _ := json.Marshal(p)
  fmt.Println(string(data))
  // {"Name":"Alice","Age":30,"City":"Lisbon"}

KEY RULE - only EXPORTED fields are (un)marshaled. This is Level 2's
exported/unexported rule again: a lowercase field is silently skipped,
no error, ever.

================================================================================
                     STRUCT TAGS FOR JSON
================================================================================

  type User struct {
      Name  string `json:"name"`             // renamed
      Email string `json:"-"`                // excluded entirely
      Bio   string `json:"bio,omitempty"`    // omitted if zero value
  }

Verified:
  Full struct:       {"name":"Alice","bio":"hi"}
  Empty bio omitted: {"name":"Alice"}

================================================================================
                 DYNAMIC JSON: THE TYPE-ASSERTION DANCE
================================================================================

When you don't know the JSON's shape ahead of time, unmarshal into
map[string]interface{} and use Level 15's type assertions to get values out:

  var v map[string]interface{}
  json.Unmarshal(data, &v)

  name, ok := v["name"].(string)     // safe two-value form
  count, ok := v["count"].(float64)  // JSON numbers are ALWAYS float64!

KEY GOTCHA - JSON numbers inside interface{} are always float64, never int.
Asserting .( int) on a JSON number PANICS. Always use .(float64) and
convert if you need an int.

================================================================================
                 RAWMESSAGE AND STREAMING
================================================================================

json.RawMessage defers parsing a sub-object until you know its shape
(e.g., based on a "kind" field) - a two-stage parse.

json.Decoder / json.Encoder stream JSON to/from an io.Reader/io.Writer -
useful for files (Level 18!), network connections, or reading many JSON
values one at a time instead of loading everything into memory first.

  dec := json.NewDecoder(reader)
  for dec.More() {
      var v MyType
      dec.Decode(&v)
  }

================================================================================
                    CUSTOM MARSHALING
================================================================================

Implement these two methods to take full control of a type's JSON format:

  func (t MyType) MarshalJSON() ([]byte, error) { ... }   // value receiver
  func (t *MyType) UnmarshalJSON(data []byte) error { ... } // pointer receiver

Common uses: enum-like types serialized as strings, custom date formats,
values that need validation on the way in.

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Unexported field, expecting it in JSON
  type T struct { name string }   // never appears in Marshal output!

✅ RIGHT
  type T struct { Name string `json:"name"` }

---

❌ WRONG: omitempty hiding a meaningful zero value
  type Account struct {
      Balance float64 `json:"balance,omitempty"`
  }
  // a real $0 balance vanishes from the JSON - can't tell zero from unset!

✅ RIGHT: drop omitempty when zero is a valid, meaningful value

---

❌ WRONG: Ignoring the error
  data, _ := json.Marshal(v)
  json.Unmarshal(input, &v)

✅ RIGHT
  data, err := json.Marshal(v)
  if err != nil { /* handle */ }

---

❌ WRONG: Asserting a JSON number as int from interface{}
  count := v["count"].(int)   // PANICS - it's float64!

✅ RIGHT
  count := v["count"].(float64)

---

❌ WRONG: Forgetting the pointer in Unmarshal
  json.Unmarshal(data, c)     // compile error

✅ RIGHT
  json.Unmarshal(data, &c)

================================================================================
                      QUICK FAQ
================================================================================

Q: Do I need a third-party JSON library?
A: No. encoding/json in the standard library covers the vast majority of
   real-world work.

Q: Why did a field just disappear from my JSON?
A: Either it's unexported (lowercase - invisible to encoding/json), or it
   has omitempty and holds its zero value.

Q: Why is my number a float when I expected an int?
A: Unmarshaling into interface{} always produces float64 for JSON numbers.
   Convert explicitly, or unmarshal into a struct with a typed int field.

Q: map[string]interface{} or a struct?
A: A struct whenever you know the shape - safer, clearer. Reach for
   map[string]interface{} only when the shape is genuinely unknown.

Q: Unmarshal vs Decoder - what's the difference?
A: Unmarshal works on a complete []byte already in memory. Decoder reads
   from an io.Reader and can decode a stream of many JSON values one at
   a time - more efficient for large or incremental data.
