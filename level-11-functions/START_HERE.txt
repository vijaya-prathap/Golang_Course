                      THE BIG PICTURE
================================================================================

What Makes Functions Worth a Whole Level?
  → In Go, functions are VALUES - you can store them in variables,
    pass them as arguments, and return them from other functions
  → Functions can return MULTIPLE values directly - no wrapper needed
  → A function literal that "closes over" outer variables (a CLOSURE)
    can carry private, mutable state between calls

Why This Matters:
  → Levels 12-16 (Pointers, Structs, Methods, Interfaces, Error Handling)
    all build directly on what you learn here
  → Higher-order functions, closures, and defer show up constantly in
    real Go code - HTTP handlers, database cleanup, retry logic, and more

================================================================================
                 MULTIPLE RETURN VALUES
================================================================================

Go functions can return more than one value - no struct or tuple needed:

  func divmod(a, b int) (int, int) {
      return a / b, a % b
  }

  q, r := divmod(17, 5)   // q = 3, r = 2
  q, _ := divmod(17, 5)   // ignore the remainder with _

================================================================================
              NAMED RETURNS AND NAKED RETURNS
================================================================================

Return values can be NAMED in the signature. A bare "return" (a "naked
return") sends back their current values:

  func minMax(nums []int) (min, max int) {
      min, max = nums[0], nums[0]
      for _, n := range nums {
          if n < min { min = n }
          if n > max { max = n }
      }
      return // naked return
  }

KEY WARNING: naked returns are fine in short functions, but they hurt
readability once a function has multiple exit points or grows long - the
reader has to scroll back up to remember what's being returned. Prefer
explicit "return value, err" in longer functions.

================================================================================
                    VARIADIC FUNCTIONS
================================================================================

A variadic parameter (marked with ...) accepts zero or more arguments,
and becomes an ordinary slice inside the function:

  func sum(nums ...int) int {
      total := 0
      for _, n := range nums {
          total += n
      }
      return total
  }

  sum(1, 2, 3)             // 6

  values := []int{10, 20, 30}
  sum(values...)           // 60 - spread a slice into the call with ...

RULE: a variadic parameter must be LAST, and a function can have only ONE.

================================================================================
              FUNCTIONS AS VALUES & HIGHER-ORDER FUNCTIONS
================================================================================

Functions have types (like func(int) int) and can be treated like any
other value:

  var fn func(int) int = double
  fn(10) // 20 - calling indirectly through a variable

  func apply(nums []int, f func(int) int) []int {
      result := make([]int, len(nums))
      for i, n := range nums {
          result[i] = f(n)
      }
      return result
  }

  apply(nums, double)  // apply is "higher-order" - it takes a function

================================================================================
              ANONYMOUS FUNCTIONS & CLOSURES
================================================================================

An anonymous function (function literal) has no name - call it right
away, store it, or pass it inline:

  result := func(a, b int) int { return a + b }(3, 4)  // called immediately
  square := func(n int) int { return n * n }           // stored in a variable

A CLOSURE additionally captures variables from its enclosing scope BY
REFERENCE - it shares and can mutate that state across every call:

  func makeCounter() func() int {
      count := 0
      return func() int {
          count++
          return count
      }
  }

  counter := makeCounter()
  counter() // 1
  counter() // 2 - SAME count, shared across calls

================================================================================
     KEY GOTCHA - LOOP VARIABLE CAPTURE (READ THIS CAREFULLY!)
================================================================================

This is Go's most famous historical gotcha - and it's FIXED on the Go
version this course uses.

THIS PROJECT'S go.mod SPECIFIES: go 1.26.5

  var funcs []func()
  for i := 0; i < 3; i++ {
      funcs = append(funcs, func() { fmt.Println(i) })
  }
  for _, f := range funcs {
      f()
  }

  VERIFIED OUTPUT ON go1.26.5:   0
                                 1
                                 2

BEFORE Go 1.22, every iteration of a for loop reused the SAME loop
variable, so all the closures above would have shared it and printed
"3 3 3" once the loop finished (they'd all see the FINAL value). Go 1.22
changed the semantics so EVERY iteration gets its own fresh copy of the
loop variable - the bug described in older blog posts and Stack Overflow
answers simply cannot happen on Go 1.22+.

If you see an old "i := i" workaround in someone else's code, it's now
harmless but unnecessary on this Go version - you don't need to add it
to new code.

================================================================================
                          RECURSION
================================================================================

A recursive function calls itself, working toward a BASE CASE:

  func factorial(n int) int {
      if n <= 1 {
          return 1 // base case
      }
      return n * factorial(n-1) // recursive case
  }

Naive recursive Fibonacci recomputes the same sub-problems repeatedly -
its runtime is exponential (O(2^n)). An iterative (or memoized) version
solves the same problem in linear time:

  func fibIterative(n int) int {
      if n < 2 { return n }
      a, b := 0, 1
      for i := 2; i <= n; i++ {
          a, b = b, a+b
      }
      return b
  }

Use recursion when the DATA is naturally recursive (trees, nested
structures); prefer a plain loop for simple linear iteration.

================================================================================
                           defer
================================================================================

defer delays a function CALL until the surrounding function returns -
commonly used for cleanup (closing files, unlocking mutexes):

  defer fmt.Println("runs when the function returns")

Multiple defers run in LIFO order (last one registered, first one run):

  defer fmt.Println("1st deferred, runs LAST")
  defer fmt.Println("2nd deferred, runs FIRST")

KEY RULE: a deferred call's ARGUMENTS are evaluated IMMEDIATELY when
defer runs - only the call itself is delayed:

  i := 0
  defer fmt.Println("i was", i) // captures 0 RIGHT NOW
  i++
  // when this function returns, it still prints "i was 0"

================================================================================
                    A SIMPLE EXAMPLE
================================================================================

package main

import "fmt"

func divmod(a, b int) (int, int) {
    return a / b, a % b
}

func makeCounter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

func main() {
    q, r := divmod(17, 5)
    fmt.Println("17 / 5 =", q, "remainder", r)

    counter := makeCounter()
    fmt.Println(counter())
    fmt.Println(counter())
}

Output:
  17 / 5 = 3 remainder 2
  1
  2

   var fn func(int) int = double     apply(nums, double)

8. RECURSION
   Base case + recursive case; prefer iteration for overlapping sub-problems

9. defer
   LIFO order; arguments evaluated immediately, call delayed

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Variadic parameter not last
  func broken(nums ...int, label string) { }

✅ RIGHT
  func fixed(label string, nums ...int) { }

---

❌ WRONG: Forgetting ... when spreading a slice
  sum(values)      // compile error - []int is not int

✅ RIGHT
  sum(values...)

---

❌ WRONG: Expecting the pre-Go-1.22 loop variable bug
  for i := 0; i < 3; i++ {
      funcs = append(funcs, func() { fmt.Println(i) })
  }
  // On go1.26.5 this prints 0, 1, 2 - NOT three copies of 3!

---

❌ WRONG: Naive recursion at scale
  fibNaive(40)      // noticeably slow - exponential time

✅ RIGHT
  fibIterative(40)  // instant - linear time

                      QUICK FAQ
================================================================================

Q: Do old blog posts about the "loop variable bug" still apply?
A: No - not on this course's Go version (go 1.26.5, which uses Go 1.22+
   semantics). Each loop iteration now gets its own copy of the loop
   variable. Old warnings were correct for their time, just outdated now.

Q: When should I use a naked return?
A: Only in short functions with one exit point. Once a function has
   multiple exit points or grows past 10-15 lines, use explicit returns.

Q: What's the difference between a closure and a regular function?
A: A closure additionally captures outer-scope variables BY REFERENCE,
   so it can read and mutate them across calls, even after the outer
   function has returned. A regular function can't do that.

Q: Why avoid naive recursive Fibonacci for large n?
A: It recomputes the same sub-problems repeatedly - O(2^n) time. Use
   iteration or memoization (cache previous results) instead.

Q: Does defer run right away?
A: The CALL is delayed until the function returns, but the ARGUMENTS to
   that call are evaluated immediately, when the defer statement runs.
