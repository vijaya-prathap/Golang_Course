================================================================================
                      THE BIG PICTURE
================================================================================

What Does Gin Add Over net/http?
  → Faster routing via a radix tree (still correct at thousands of routes)
  → Built-in JSON binding + validation via struct tags
  → Composable middleware, chained with c.Next()
  → Much less boilerplate per handler

What Gin Does NOT Change:
  → *gin.Context wraps the same *http.Request / http.ResponseWriter you
    already know from Level 27
  → HTTP semantics (status codes, methods, headers) are unchanged
  → Testing still uses httptest.NewRequest + httptest.NewRecorder

================================================================================
                 BEFORE / AFTER: net/http vs GIN
================================================================================

  // net/http (Level 27 style)
  func getUserHandler(w http.ResponseWriter, r *http.Request) {
      id := r.PathValue("id")
      w.Header().Set("Content-Type", "application/json")
      json.NewEncoder(w).Encode(map[string]string{"user_id": id})
  }
  mux.HandleFunc("GET /users/{id}", getUserHandler)

  // Gin
  func getUserHandler(c *gin.Context) {
      id := c.Param("id")
      c.JSON(http.StatusOK, gin.H{"user_id": id})
  }
  router.GET("/users/:id", getUserHandler)

================================================================================
                 SETUP: gin.Default() vs gin.New()
================================================================================

  router := gin.Default() // gin.New() + Logger() + Recovery() middleware
  router := gin.New()     // a bare engine - no middleware attached

gin.Default() is not magic - it's just gin.New() with two Use() calls
already made for you. Exercise 1 proves this by rebuilding it by hand.

================================================================================
                    ROUTING & ROUTE GROUPS
================================================================================

  router.GET("/users/:id", handler)          // path parameter -> c.Param("id")
  router.GET("/files/*filepath", handler)    // wildcard catch-all

  v1 := router.Group("/api/v1")
  v1.GET("/users", listUsersV1)              // -> /api/v1/users

================================================================================
                 JSON BINDING WITH VALIDATION
================================================================================

  type CreateUserInput struct {
      Name  string `json:"name" binding:"required"`
      Email string `json:"email" binding:"required,email"`
  }

  var input CreateUserInput
  if err := c.ShouldBindJSON(&input); err != nil {
      c.JSON(400, gin.H{"error": err.Error()})
      return
  }

KEY GOTCHA - No binding tag means no validation:
  A field with only a json tag silently accepts the zero value if the
  client omits it. Tag every field that must be present.

================================================================================
                       MIDDLEWARE
================================================================================

  func myMiddleware() gin.HandlerFunc {
      return func(c *gin.Context) {
          // ...before...
          c.Next()   // hands off to the next middleware/handler
          // ...after...
      }
  }

  router.Use(myMiddleware())                   // global
  router.GET("/x", myMiddleware(), handler)     // per-route
  group.Use(myMiddleware())                     // per-group

KEY GOTCHA - Forgetting c.Next() means nothing downstream ever runs.
KEY GOTCHA - To stop the chain, call c.AbortWithStatusJSON(...), not just
  a plain return - a bare return doesn't tell Gin to stop, and the next
  handler still runs.

================================================================================
                 BUILT-IN RECOVERY MIDDLEWARE
================================================================================

Level 16 taught you that an unrecovered panic crashes the whole program
(exit status 2). gin.Default()'s Recovery() middleware catches a panic
inside any handler and turns it into a clean 500 response instead - the
server keeps running and serves the very next request normally.

================================================================================
                      TESTING GIN HANDLERS
================================================================================

  gin.SetMode(gin.TestMode)
  router := SetupRouter()

  req := httptest.NewRequest(http.MethodGet, "/ping", nil)
  w := httptest.NewRecorder()
  router.ServeHTTP(w, req)

  // assert on w.Code and w.Body.String()

This is the exact same httptest pattern Level 26 previewed and Level 27
used in full - *gin.Engine is an http.Handler, so nothing new to learn here.

================================================================================
                    KEY CONCEPTS SUMMARY
================================================================================

1. SETUP
   gin.Default() = gin.New() + Logger() + Recovery()

2. ROUTING
   router.GET/POST/PUT/DELETE, :param, *wildcard, router.Group(prefix)

3. INPUT
   c.Param, c.Query/c.DefaultQuery, c.ShouldBindJSON + binding tags

4. OUTPUT
   c.JSON, c.String, c.Status

5. MIDDLEWARE
   gin.HandlerFunc + c.Next() to continue, c.Abort... to stop

6. RECOVERY
   gin.Default()'s Recovery() turns a panic into a clean 500

7. TESTING
   httptest.NewRequest + httptest.NewRecorder + router.ServeHTTP

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: A struct field with no binding tag
  type Input struct { Age int `json:"age"` }   // missing age silently -> 0

✅ RIGHT
  type Input struct { Age int `json:"age" binding:"required"` }

---

❌ WRONG: Binding the same request body twice
  c.ShouldBindJSON(&a)
  c.ShouldBindJSON(&b)   // body already drained - fails or comes back empty

✅ RIGHT: Bind once into one struct

---

❌ WRONG: Ignoring the error from ShouldBindJSON
  c.ShouldBindJSON(&input)
  save(input)   // input may be invalid and you'll never know

✅ RIGHT: Always check the error before using the bound value

---

❌ WRONG: Attaching group middleware after routes are already registered
  v1.GET("/books", listBooks)
  v1.Use(authMiddleware())   // too late for /books

✅ RIGHT: Call Use() before registering routes that need it

================================================================================
                      QUICK FAQ
================================================================================

Q: Why does this level need internet access?
A: Gin is a real third-party package, not part of the standard library.
   `go get` fetches it from the Go module proxy the first time; after that
   it's cached locally and you're offline-safe for that version.

Q: Is gin.Default() doing something I can't replicate myself?
A: No - it's gin.New() with gin.Logger() and gin.Recovery() attached via
   Use(). Exercise 1 rebuilds it by hand to prove it.

Q: What's the difference between BindJSON and ShouldBindJSON?
A: BindJSON auto-writes a 400 response on failure. ShouldBindJSON just
   returns the error so you control the response format - prefer this.

Q: Does Gin replace what I learned about net/http in Level 27?
A: No - *gin.Context wraps the same *http.Request / http.ResponseWriter.
   Everything about HTTP semantics and testing with httptest still applies.

Q: Should I use Gin for every project from now on?
A: No. Gin earns its keep on larger APIs with lots of routes and
   validation needs. Plain net/http is often better for small services or
   when you want zero non-standard-library dependencies.
