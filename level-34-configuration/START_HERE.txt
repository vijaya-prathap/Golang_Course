================================================================================
                      THE BIG PICTURE
================================================================================

What is Configuration?
  → Settings that change depending on WHERE a program runs, kept OUT of
    the compiled code
  → Sources: hardcoded defaults, environment variables, command-line flags,
    and (for local dev) a .env file
  → The goal: one binary, deployed unchanged everywhere, that behaves
    correctly because of what's fed to it at startup

Why Configuration Matters:
  → A database URL, a port, an API key, a debug flag - all of these differ
    between dev/staging/production
  → Hardcoding any of them means recompiling (or branching code) for every
    environment - configuration removes that need entirely

================================================================================
              os.Getenv vs os.LookupEnv
================================================================================

  os.Getenv("KEY")           -> always a string; "" means EITHER unset
                                 OR explicitly set to empty
  os.LookupEnv("KEY")        -> (string, bool); the bool tells you which

  value := os.Getenv("APP_NAME")
  // "" whether APP_NAME was never set, or set to ""

  value, ok := os.LookupEnv("APP_NAME")
  // ok == false -> never set
  // ok == true, value == "" -> explicitly set to empty
  // ok == true, value == "MyApp" -> set to "MyApp"

================================================================================
                    THE flag PACKAGE
================================================================================

  host := flag.String("host", "localhost", "server host")
  port := flag.Int("port", 8080, "server port")
  debug := flag.Bool("debug", false, "enable debug mode")

  flag.Parse() // MUST run before reading *host, *port, *debug

  go run main.go                     -> every flag = its default
  go run main.go -port=9090          -> port=9090, rest = default

================================================================================
                 A TYPED Config STRUCT
================================================================================

  type Config struct {
      Host string
      Port string
  }

  func LoadConfig() Config {
      return Config{
          Host: getEnvOrDefault("APP_HOST", "0.0.0.0"),
          Port: getEnvOrDefault("APP_PORT", "8080"),
      }
  }

One function knows where settings come from. Everything else just
receives a Config - never scattered os.Getenv calls.

================================================================================
              CONFIG PRECEDENCE: flags > env > defaults
================================================================================

  func resolve(flagVal string, flagSet bool, envKey, def string) (string, string) {
      if flagSet {
          return flagVal, "flag"
      }
      if envVal, ok := os.LookupEnv(envKey); ok {
          return envVal, "env"
      }
      return def, "default"
  }

  Flag passed?   Env set?   Winner
  No             No         default
  No             Yes        env
  Yes            No         flag
  Yes            Yes        flag

================================================================================
                 FAIL-FAST VALIDATION
================================================================================

Check every required setting ONCE, at startup - never discover a missing
value three requests deep into production traffic.

  func (c Config) Validate() error {
      if c.DatabaseURL == "" {
          return errors.New("DATABASE_URL is required but not set")
      }
      return nil
  }

  cfg := LoadConfig()
  if err := cfg.Validate(); err != nil {
      log.Fatal(err) // bridges Level 33: log it, then exit immediately
  }

================================================================================
              TYPE CONVERSION FOR ENV VARS
================================================================================

Every env var is a string. Parse it, and always check the error:

  n, err := strconv.Atoi(raw)             // string -> int
  b, err := strconv.ParseBool(raw)        // string -> bool
  d, err := time.ParseDuration(raw)       // string -> time.Duration

  if err != nil {
      return fmt.Errorf("invalid value for %s: %q: %w", key, raw, err)
  }

================================================================================
              HAND-ROLLED .env FILE SUPPORT
================================================================================

A .env file is just KEY=VALUE lines - no library needed to read one:

  scanner := bufio.NewScanner(file)
  for scanner.Scan() {
      line := strings.TrimSpace(scanner.Text())
      if line == "" || strings.HasPrefix(line, "#") {
          continue // skip blank lines and comments
      }
      parts := strings.SplitN(line, "=", 2)
      result[strings.TrimSpace(parts[0])] = strings.TrimSpace(parts[1])
  }

KEY RULE: a .env file should never override a variable that's already a
real environment variable - it only fills gaps for local dev convenience.

================================================================================
                      A SIMPLE EXAMPLE
================================================================================

package main

import (
    "fmt"
    "os"
)

type Config struct {
    Port string
}

func LoadConfig() Config {
    port, ok := os.LookupEnv("APP_PORT")
    if !ok {
        port = "8080"
    }
    return Config{Port: port}
}

func main() {
    cfg := LoadConfig()
    fmt.Printf("Listening on port %s\n", cfg.Port)
}

Output (no APP_PORT set):
  Listening on port 8080

Output (APP_PORT=9000 go run main.go):
  Listening on port 9000

4. VALIDATION
   Validate() at startup, log.Fatal on failure - fail fast, always

5. TYPE CONVERSION
   strconv/time.ParseDuration, always checking the error

6. LOCAL DEV CONVENIENCE
   Hand-rolled .env parser; never overrides real env vars

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Silent zero-value fallback for a required setting
  cfg.DatabaseURL = os.Getenv("DATABASE_URL")   // "" starts "successfully"

✅ RIGHT
  if cfg.DatabaseURL == "" { return errors.New("DATABASE_URL is required") }

---

❌ WRONG: Config-loading code scattered through business logic
  func ProcessOrder() { timeout := os.Getenv("ORDER_TIMEOUT") }

✅ RIGHT: Load once, pass a typed Config down
  func ProcessOrder(cfg Config) { /* uses cfg.OrderTimeout */ }

---

❌ WRONG: Using Getenv when "unset vs empty" actually matters
  flags := os.Getenv("FEATURE_FLAGS")

✅ RIGHT: Use LookupEnv
  if flags, ok := os.LookupEnv("FEATURE_FLAGS"); ok { /* respect it exactly */ }

---

❌ WRONG: A .env loader that always calls os.Setenv, clobbering real vars

✅ RIGHT: Only set if not already set
  if _, alreadySet := os.LookupEnv(key); !alreadySet { os.Setenv(key, value) }

================================================================================
                      QUICK FAQ
================================================================================

Q: Why not just use os.Getenv everywhere?
A: Scattered os.Getenv calls give you no single place to see every setting
   a program needs, no consistent defaults, and no way to tell "unset"
   from "empty" where that matters. A Config struct plus LoadConfig() fixes
   all three.

Q: Do I need Viper or another config library for this level?
A: No - every exercise uses only the standard library (os, flag, strconv,
   time, bufio) and runs fully offline. Third-party libraries are further
   reading only, never imported here.

Q: Why do flags override environment variables?
A: Env vars are usually set once per deployment; flags are passed
   explicitly for one specific run, making them the most deliberate,
   most recent instruction - so they win.

Q: Why shouldn't .env override a real environment variable?
A: A real, exported environment variable was set deliberately (often by
   your deployment platform) and should never be silently overridden by
   a leftover .env file. .env is for filling gaps in local dev only.

Q: What does "fail fast" actually save me from?
A: A missing DATABASE_URL caught by Validate() at startup is one obvious
   error message before the server even starts. Left uncaught, the same
   problem might not surface until a real request needs it - possibly in
   production.
