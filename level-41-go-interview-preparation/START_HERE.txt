                      THE BIG PICTURE
================================================================================

How Do Go Interviews Actually Work?
  → Usually a mix of: (a) language fundamentals/gotchas, (b) a coding
    challenge solved live, and (c) sometimes a system design discussion
  → Interviewers watch HOW you think more than whether you're instantly
    perfect - narrating your reasoning matters as much as the answer

Why This Level Matters:
  → Nearly everything a Go interviewer asks is one of a small number of
    classic gotchas or coding patterns, asked in disguise
  → Knowing that small set DEEPLY - and being able to verify it yourself,
    not just recite it - is what separates confident answers from guesses

================================================================================
                 THE SEVEN CLASSIC GOTCHAS (ALL VERIFIED)
================================================================================

1. SLICE / append() ALIASING (Level 8)
   Slicing shares an underlying array; append() can silently overwrite
   a sibling slice's data when there's spare capacity.

2. LOOP VARIABLE CAPTURE (Level 11/20)
   Pre-Go 1.22: one variable reused every iteration. Go 1.22+: each
   iteration gets its own copy. This project's go.mod says go 1.26.5 -
   verified to use the new, per-iteration behavior.

3. nil INTERFACE vs TYPED-NIL (Level 15) *** the most commonly asked ***
   An interface is only == nil if BOTH its type and value are nil. A nil
   pointer wrapped in a non-nil interface type is NOT a nil interface.

4. MAP ITERATION ORDER (Level 6/10)
   Randomized on purpose, verified across separate runs of identical code.

5. UNCOMPARABLE STRUCTS/ARRAYS (Level 7/13)
   A struct with a slice/map/func field fails == at COMPILE time, not
   runtime. Use reflect.DeepEqual instead.

6. GOROUTINE LEAKS (Level 20)
   A goroutine blocked forever on a channel nobody sends to never gets
   collected - verified by watching runtime.NumGoroutine() climb and stay up.

7. CHANNEL DEADLOCKS & nil CHANNELS (Level 21/22)
   Sending with no possible receiver crashes the whole program. A nil
   channel just blocks forever, silently - useful for disabling a select case.

================================================================================
                    THE SIX CODING-CHALLENGE PATTERNS
================================================================================

  Reverse a string (Unicode-safe)  -> []rune, two-pointer swap
  Cycle detection                   -> slow/fast pointers, O(1) space
  First non-repeating character     -> frequency map + ordered pass
  LRU cache                         -> map + container/list
  Merge overlapping intervals       -> sort by start, sweep once
  Worker pool                       -> jobs chan in, results chan out, WaitGroup

================================================================================

================================================================================

  Clarify -> Design -> Code -> Tradeoffs

Ask before you assume. Sketch before you dive. Narrate while you build.
Discuss what you'd change before you call it done.

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Memorizing answers instead of understanding why
  Reciting "nil interface" rules without understanding the type+value pair

✅ RIGHT: Understand the mechanism, not just the sentence describing it

---

❌ WRONG: Not asking clarifying questions before coding
  Diving into "reverse a string" without asking about Unicode or empty input

✅ RIGHT: Clarify scope and edge cases before writing a line of code

---

❌ WRONG: Ignoring edge cases like empty input, nil, or zero values
  Only handling the happy path

✅ RIGHT: Name empty/nil/zero-value cases out loud, unprompted

---

❌ WRONG: Not testing your own solution before saying "done"
  "I think this works"

✅ RIGHT: Run it, or trace it by hand, before declaring it finished

                      QUICK FAQ
================================================================================

Q: Do I need to memorize all 42 levels before an interview?
A: No - use the Section 8 checklist in README.md to find your weakest 3-5
   levels and focus your remaining prep time there.

Q: What's the single most important gotcha to know cold?
A: The nil-interface vs typed-nil trap. It's the most commonly asked
   Go-specific gotcha in real interviews.

Q: What if I don't know the answer to a question?
A: Say so honestly, and explain how you'd find out. A confident wrong
   guess reads worse than an honest "I'm not sure, here's how I'd check."

Q: Is this level teaching new Go features?
A: No - it's a review level. Every gotcha and pattern here comes from a
   level you've already completed; this just compresses it into interview
   shape and verifies it all for real, one more time.
