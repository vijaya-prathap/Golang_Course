================================================================================
                      THE BIG PICTURE
================================================================================

What is a Condition?
  → A boolean expression Go checks to decide what runs
  → Built from the comparison/logical operators you learned in Level 4
  → if and switch are the two ways Go branches on conditions

Why Conditions Matter:
  → Every real program makes decisions: valid or invalid input, which
    branch of logic to run, which error to report
  → Mastering if/switch is mastering control flow itself

================================================================================
                    THE if STATEMENT
================================================================================

The most basic form:

  if condition {
      // runs only if condition is true
  }

KEY RULE: The opening brace MUST be on the same line as if!

  ✅ RIGHT                    ❌ WRONG (compile error)
  if age >= 18 {              if age >= 18
      ...                     {
  }                               ...
                              }

================================================================================
                    if/else AND else if CHAINS
================================================================================

  if score >= 90 {
      grade = "A"
  } else if score >= 80 {
      grade = "B"
  } else {
      grade = "F"
  }

KEY RULE: Go checks conditions top-to-bottom and runs the FIRST true one.
The rest are never even checked.

THIS MEANS: order matters for overlapping ranges!

  ✅ RIGHT - highest threshold first
  if score >= 90 { "A" } else if score >= 70 { "C" }

  ❌ WRONG - score=95 wrongly gets "C" because it's checked first
  if score >= 70 { "C" } else if score >= 90 { "A" }

================================================================================
                 THE SHORT-INIT PATTERN
================================================================================

if can run a short statement BEFORE the condition. The variable it creates
is scoped ONLY to that if/else block.

  if value, err := strconv.Atoi(s); err == nil {
      // use value here
  } else {
      // handle err here
  }
  // value and err do NOT exist here!

This is used everywhere in idiomatic Go - especially for:
  - Error checking:     if err := doThing(); err != nil { ... }
  - Map lookups:        if v, ok := myMap[key]; ok { ... }

================================================================================
                      THE switch STATEMENT
================================================================================

switch compares one value against many cases:

  switch day {
  case "Saturday", "Sunday":
      fmt.Println("Weekend")
  default:
      fmt.Println("Weekday")
  }

IMPORTANT: Unlike C or Java, Go's switch does NOT fall through by default!
Each case automatically stops after its own block runs.

A CONDITIONLESS switch works like a clean if/else-if chain:

  switch {
  case score >= 90:
      grade = "A"
  case score >= 80:
      grade = "B"
  default:
      grade = "F"
  }

================================================================================
                          fallthrough
================================================================================

If you actually WANT the next case to run too, say so explicitly:

  switch n {
  case 1:
      fmt.Println("one")
      fallthrough      // forces case 2's body to run next
  case 2:
      fmt.Println("two")
  }

fallthrough is rare in idiomatic Go - most switches read better without it.

================================================================================
                 AVOIDING DEEP NESTING
================================================================================

Deeply nested if statements get hard to follow:

  ❌ NESTED
  if active {
      if verified {
          if hasPermission {
              return "OK"
          }
      }
  }

  ✅ FLAT (early returns / guard clauses)
  if !active { return "Inactive" }
  if !verified { return "Not verified" }
  if !hasPermission { return "No permission" }
  return "OK"

Both versions do the same thing, but the flat version is far easier to scan.

================================================================================
                    A SIMPLE EXAMPLE
================================================================================

package main

import "fmt"

func main() {
    age := 20

    if age >= 18 {
        fmt.Println("Adult")
    } else {
        fmt.Println("Minor")
    }

    switch {
    case age < 13:
        fmt.Println("Child")
    case age < 20:
        fmt.Println("Teen")
    default:
        fmt.Println("Adult")
    }
}

Output:
  Adult
  Adult

================================================================================
                      KEY CONCEPTS SUMMARY
================================================================================

1. IF / ELSE
   if cond { } else if cond2 { } else { }
   First true condition wins. Order matters for overlapping ranges.

2. SHORT INIT
   if x := f(); x > 0 { }
   x is scoped ONLY to the if/else.

3. SWITCH
   switch value { case a, b: ... default: ... }
   No automatic fallthrough - each case auto-breaks.

4. CONDITIONLESS SWITCH
   switch { case cond1: ... }
   A cleaner alternative to long if/else-if chains.

5. FALLTHROUGH
   Explicitly runs the next case's body. Rarely needed.

6. FLATTENING
   Prefer early returns over deeply nested if statements.

================================================================================
                    COMMON MISTAKES TO AVOID
================================================================================

❌ WRONG: Checking the lower threshold first
  if score >= 70 { "C" } else if score >= 90 { "A" }

✅ RIGHT: Check the highest threshold first
  if score >= 90 { "A" } else if score >= 70 { "C" }

---

❌ WRONG: Expecting Go's switch to fall through automatically
  switch 2 {
  case 2: fmt.Println("two")
  case 3: fmt.Println("three")   // does NOT run for n=2
  }

✅ RIGHT: Use fallthrough if you want that behavior

---

❌ WRONG: Brace on its own line
  if x > 5
  {
  }

✅ RIGHT: Brace on the same line
  if x > 5 {
  }

---

❌ WRONG: Deep nesting
  if a { if b { if c { doWork() } } }

✅ RIGHT: Early returns
  if !a { return }
  if !b { return }
  if !c { return }
  doWork()

================================================================================
                      QUICK FAQ
================================================================================

Q: When should I use if vs switch?
A: if/else for one or two conditions. switch when comparing one value
   against many cases, or a conditionless switch for many independent
   conditions/ranges.

Q: Does Go's switch fall through like C or Java?
A: No. Each case auto-breaks. Use fallthrough to explicitly opt in.

Q: What's the short-init form actually for?
A: Scoping a helper variable (an error, a lookup result) so it only
   exists where it's needed.

Q: Why does order matter in if/else-if chains?
A: Go runs the FIRST true condition. For overlapping ranges, check the
   most specific (usually highest) condition first.

Q: Is nesting bad?
A: Not always, but two or three levels deep it usually gets harder to
   read. Prefer early returns when every branch would exit anyway.
